# Contributing

Quine welcomes public input through GitHub issues and proposals.

## Welcome

- reproducible bug reports
- feature and improvement ideas
- design feedback
- documentation corrections

For a useful report, include:

- exact Quine revision
- operating system and Python/uv versions
- scripted versus real-provider mode
- minimal reproduction
- exact error and relevant redacted logs
- whether the issue touches security, secrets, state migration, validation, promotion, or rollback

## Code pull requests

External code pull requests are not accepted at launch. Quine is currently owner-controlled so future versions can be relicensed or dual-licensed without tracing additional copyright holders. A contributor agreement or equivalent policy will be published before code pull requests are accepted.

Please do not send unsolicited code patches until that policy exists. They may be closed without review.

## Keep reports safe

Never post credentials, private conversations, uploaded documents, generated customer code, or vulnerability details in a public issue. Use the private reporting route described in [SECURITY.md](SECURITY.md) when it is available after public release.
